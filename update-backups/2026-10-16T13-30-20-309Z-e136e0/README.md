# 青禾 · 发展党员材料审核工作台（本地项目）

本项目是已展示网页小样的独立本地源码，使用原生 HTML、CSS、JavaScript。内置 12 名虚拟学生和 53 份材料，无前端构建步骤，无 npm 第三方依赖。

## 1. 快速启动

先安装 Node.js 18 或更高版本。解压 ZIP，进入 `qinghe-local` 文件夹。

### Windows

双击 `start-windows.bat`，保持终端窗口打开，然后浏览器访问：

http://127.0.0.1:3000

### Windows / macOS / Linux 命令行

在项目目录运行：

```bash
npm start
```

也可直接运行 `node server.mjs`，无需先执行 `npm install`。
macOS 可用终端运行 `sh start-macos.command`。

修改 `public/` 中的文件后，刷新浏览器即可。若缓存未更新，可按 Ctrl+F5（Windows）强制刷新。按 Ctrl+C 停止服务。

### 没有 Node.js，但已安装 Python 3

```bash
python -m http.server 3000 --bind 127.0.0.1 --directory public
```

macOS/Linux 环境可能需要使用 `python3`。仍访问上面的本地地址。

### 端口被占用

PowerShell：`$env:PORT=3001; npm start`

macOS/Linux：`PORT=3001 npm start`

此时访问 `http://127.0.0.1:3001`。不同端口的浏览器数据各自独立。

## 2. 文件分工

| 文件 | 用途 / 修改位置 |
| --- | --- |
| `public/index.html` | 网页入口、标题、资源引用 |
| `public/styles.css` | 配色、排版、布局和移动端样式 |
| `public/model.js` | 虚拟数据、阶段与清单、日期与文本规则 |
| `public/app.js` | 页面渲染、搜索筛选、上传、反馈、人工处理、日志 |
| `server.mjs` | 本地静态服务器，仅监听本机地址 |
| `package.json` | 启动、语法检查和测试命令 |
| `data/demo-state.json` | 初始虚拟状态快照，供查看字段和对接接口参考 |
| `docs/HANDOFF.md` | 队友交接说明、数据结构、功能边界和改造入口 |
| `tests/model.test.cjs` | 规则逻辑回归测试 |

`public/` 就是完整可编辑源码，不是压缩编译产物。
`data/demo-state.json` 是参考快照，页面不会自动读取它；要更换启动数据，请修改 `model.js` 的 `seed()`，或按交接文档接入读取接口。

## 3. 建议演示顺序

1. 打开“工作概览”，查看批次和阶段统计。
2. 进入“材料审核”，打开“林沐”。
3. 查看培养周期、签字、规范名称错字提示，并定位到材料。
4. 在“校对提取结果”或“时间节点”中修改虚拟字段，重新校验。
5. 生成整改清单，复制或下载 TXT。
6. 切换“学生整改”，提交复核；在“审核日志”查看记录。
7. 在“审核规则库”调整演示阈值，观察结果变化。

## 4. 数据保存与重置

状态保存在浏览器 `localStorage` 的 `qinghe-demo-v1` 键中；修改源码里的初始数据不会覆盖已有浏览器状态。

修改 `seed()` 后，请进入“审核规则库 → 恢复初始演示”，或在开发者工具中清除此键再刷新。需要保留当前修改时，先点击“导出演示数据”。

在线网页、不同浏览器、不同端口的本地数据不会自动同步。代码包包含初始虚拟样本，不包含你在在线页面操作后保存的浏览器状态。

## 5. 当前实现范围

已实现：分阶段材料清单、文件登记、TXT 正文读取、结构化时间校验、签字盖章字段核对、示例名称错字与占位文本检查、人工核实意见、整改清单、演示复核、规则调整、CSV/JSON 导出和操作日志。

未接入：PDF/Word/图片 OCR、自动版式分析、大模型语义核查、服务端数据库、真实账号权限、通知发送和多人协同。现有“学生视图”和“审核员”是演示交互，不是身份认证与权限控制。

人物、材料、规则阈值均为虚构。正式材料清单、制度来源、日期口径和例外需要由校方确认。系统只辅助材料核验，不对个人思想、政治表现或发展资格作自动评分与决定。
